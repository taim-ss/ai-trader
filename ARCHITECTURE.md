# AI Trader: architecture and implementation status

Status checked 26 October 2026: Phase 3 was approved; Phase 4 is incomplete.
The local engine supports historical research and read-only demo rebalance planning.
Broker submission is disabled in the CLI. No live adapter is implemented.

## Verified implementation

| Component | Current behavior |
|---|---|
| Intake / import | Validated profile and holdings CSV; rejects nonfinite financial values |
| Diagnosis | Concentration only; correlation, fees and events are still planned |
| Strategy | Deterministic 252-session momentum, skipping 21 sessions; not an LLM trading agent |
| Risk | Validated configuration, target caps, gross exposure, per-order EUR cap and sell truncation |
| Broker | Demo-only adapter; CLI performs GET requests only, with canonical ticker and USD-currency checks |
| Backtest | Holdings drift; month-end signals execute at next observed session close; assumptions in reports/REPORT.md |
| Logging / calibration | Decision log and explicit binary-forecast Brier scorer; supplied verified outcomes required |
| Dashboard | Static offline reports/dashboard.html; private decision details only with --private under logs/ |

The 14-ETF research universe does not implement the owner's complete stock watchlist.
The optional core allocation is a strategy parameter, not a profile-driven strategy selector.
Multi-agent fundamentals/news/technical/macro analysis and automatic outcome collection are not implemented.
No paper fills, live results, or profitable trading skill have been established.

## Scope and constraints

- Paper only until CHECKPOINT 4 with an explicit yes from the owner. Live modes are off by default.
- Broker for the paper phase: Trading 212 practice environment (`https://demo.trading212.com/api/v0`). Authentication is HTTP Basic with an API key and secret, and the key pair is generated by the owner in the app ([docs](https://docs.trading212.com/api)).
- Real orders on the Revolut account are not automated; Revolut has no public stock-trading API found in Phase 2.
- Secrets live only in environment variables. Nothing secret is committed or pasted into chat.
- Evaluation window: 3 months (owner decision, 25 Oct 2026).

## Two layers

1. **Public engine (this repo).** One-size-fits-all. Profile in, diagnosis and decisions out. No personal data in the repo.
2. **Private instance (planned integration).** The owner's profile, holdings and rules belong in local git-ignored configuration. Intake/import functions exist, but the rebalance CLI does not yet wire a private profile into strategy selection.

## Intended pipeline (not all stages implemented)

```
profile + portfolio (CSV / config)
   -> diagnosis (concentration, correlation, fees, events)
   -> strategy engine (candidate strategies per profile)
   -> analysis agents (fundamentals, news, technicals, macro, risk, judge)
   -> target weights
   -> risk engine (hard limits; the LLM cannot override)
   -> broker adapter (paper: Trading 212 demo) or manual advice output
   -> decision log (JSON, one forecast ID per decision)
   -> calibration (scores forecasts when the resolution date passes)
```

## Modes

`advise` -> `paper` -> `live-with-approval` -> `live-auto`

- `advise`: writes a report, places nothing. Default for new users.
- `paper`: orders go to the Trading 212 demo environment only.
- `live-with-approval`: a human confirms each order. Not enabled before CHECKPOINT 4.
- `live-auto`: off by default; requires a separate config flag and owner approval.

## Hard risk engine and execution gate

Limits are read from `config/risk_limits.yaml`:

- max position weight (default 15% per name)
- max daily loss (halts trading for the day)
- max drawdown kill switch (halts all trading until a human resets it)
- no leverage, no shorting, no options by default
- max order size in EUR
- cooldown after a loss threshold

Target and per-order violations block a plan; oversized orders are not resized to fit.
Quantities are truncated to four decimals toward zero to avoid rounding a sell above holdings.
EUR order caps explicitly convert account-currency values to EUR.

Persistent daily-loss accounting, a latched drawdown halt, consecutive-loss cooldown,
cash/pending-order checks, executable-price validation and a recoverable per-order journal
are not implemented in the execution path. Therefore `scripts/paper_rebalance.py --execute`
returns exit code 2 before credentials or network access. This gate must stay in place
until those controls and order reconciliation are implemented and tested.
The low-level demo adapter still has a submission method for mocked adapter tests;
it must not be used to bypass the CLI gate.

## Calibration loop

Every decision gets an ID; that alone is not a forecast. A scoreable forecast additionally
requires an explicit binary event, probability and resolution date. `calibration.py` scores
only after that date has passed and only when supplied a verified boolean outcome.
The dashboard reports Brier scores and a reliability chart when such evidence exists.
The deterministic strategy does not invent probabilities. Outcome ingestion and scheduling
are still manual, and no calibration record exists yet.

## AI signal layer (added 27 Oct 2026)

The analyst prompts live in git-ignored `private/prompts/`; the private watchlist and live-sleeve
config are `config/private_watchlist.yaml` and `config/private_live.yaml`.
An analyst run writes `data/ai_signals/<date>-<run>.json`. `ai_trader.ai_signal.parse_signal()`
validates it (tradable watchlist symbol, risk caps, written reason per weight, per-name EUR cap,
at most 5 positions, signal not stale) and rejects instead of repairing.
`live_gate_blockers()` lists every reason the live sleeve may not trade; it is never empty while
`LIVE_EXECUTION_IMPLEMENTED` is False.
Wired for the demo account (27 Oct 2026): `scripts/paper_rebalance.py --signal FILE` validates the
signal, restricts it to unique USD-listed watchlist instruments (EUR-listed entries are refused, not
dropped), fetches quote-only market data (`load_demo_quotes`, no price history, so recent listings work),
plans against the EUR sleeve and hands one order per run to the unchanged `execute_demo_plan`, so the
journal, risk ledger, reconciliation, freshness and cap checks all still apply. Scoreable forecasts in the
signal are logged once per cycle after a clean `--execute` run. Without `--signal` the runner still uses the
momentum baseline. There is no live order adapter.
